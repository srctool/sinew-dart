# Changelog

All notable changes to Sinew for Dart and Flutter are documented here. Every package shares one version (lockstep); each package also keeps its own CHANGELOG for pub.dev.

## [Unreleased]
- S7 pana on every package in CI (#39): now that 1.0.0 is on pub.dev, every package can be scored.
  - The `publish-check` job runs `tool/check_pana.sh --all` (it installs `webp` first, since pana needs `cwebp` for screenshots), so a package that stops scoring every point fails the pull request. pub.dev gives all 14 packages 160 of 160.
- Flutter 3.50 (stable since the 1.0.0 release): Material moved out of the framework, and the Android Gradle Plugin floor rose.
  - `sinew_devtools_ui` and the example import Material from `package:material_ui/material_ui.dart` (`material_ui` ^1.11.0, which needs only Flutter 3.47), instead of the now-deprecated `package:flutter/material.dart`. The code is otherwise unchanged. `--fatal-infos` turned the deprecation into a CI failure on 3.50.
  - The example's Android Gradle Plugin is 9.1.1, the minimum Flutter 3.50 accepts.
- S7 publish dry run in CI (#39): a package that would fail to publish fails the pull request, not release day.
  - The `publish-check` job runs `melos publish --dry-run --yes`, which validates every package as `dart pub publish --dry-run` does (a LICENSE, a README, the files it would upload), and `tool/check_pana.sh`, which scores the packages with pana and fails unless each gets every point.
  - pana runs `pub get` on the package, so it can only resolve the packages with no Sinew dependency (`sinew_models`, `sinew_presentation`, `sinew_security`) until Sinew is on pub.dev. `tool/check_pana.sh --all` covers every package, for after the first publish.
- S7 Package READMEs, examples and pub.dev metadata (#85): every package is ready for its page on pub.dev.
  - A real README for each of the 14 packages: what it is for, features, install, usage, related packages and links. The setup text that `sinew_security`, `sinew_storage` and `sinew_riverpod_providers` already had (CMake for `webcrypto`, the biometric setup, the Riverpod overrides) is kept.
  - An `example/` folder in each: a runnable `main.dart` for `sinew_models`, `sinew_exception`, `sinew_paging` and `sinew_presentation`, and an `example/README.md` for the Flutter packages that points at the example app.
  - `documentation` and `topics` in every `pubspec.yaml`, and three screenshots for `sinew_devtools_ui`, made with a real font by `test/screenshots_test.dart` (it only runs with `SINEW_SCREENSHOTS=1`).
  - `pana` gives `sinew_models` and `sinew_presentation` 160 of 160, the two packages with no unpublished Sinew dependency. The names in every README were checked against the code.
- S7 Camouflage from pub.dev (#83): Sinew builds against Camouflage's released packages instead of their source.
  - `sinew_camouflage` depends on `camouflage_core: ^0.1.1` and the example on `camouflage_skin_minimal: ^0.1.1`. The `git` dependencies, the workspace's `dependency_overrides` and `publish_to: none` are gone, so `sinew_camouflage` can be published.
  - Nothing Sinew uses changed between the old pin and 0.1.1 (`CamoTouchSemantics`, `CamoClipRRect` and accessibility fixes in components Sinew doesn't use).
- S6 devtools gating in CI (#47): the `devtools-gating` job proves production builds carry no devtools code.
  - `tool/devtools_gating.sh` builds the example for one target (APK, iOS, web JS, web Wasm), mode and flavor, and counts `devToolsMarker` in the compiled output (`libapp.so`, `App.framework`, `main.dart.js`, `main.dart.wasm`).
  - CI runs it for the production release and profile builds, which must not contain the marker, and for a staging release build, which must.
- S6 `sinew_devtools` (#46): `DevToolsGate`.
  - `DevToolsGate.flavor` (the `SINEW_FLAVOR` define) and `DevToolsGate.enabled`, a `const`: true in debug, and in release or profile for a non-production flavor; false for `production` or no define, so a forgotten define fails safe.
  - `DevToolsGate.assertMatchesFlavor()` throws a `StateError` in every build mode when the define names another flavor than the one being run (`appFlavor`). A missing define, or an app without flavors, passes.
  - `SinewDevTools` and `DevToolsMenuItem` check the gate themselves too, so a production build that forgot it in `main` still shows only the app and drops their code.
  - The example runs through the gate. A release web build with `SINEW_FLAVOR=production` contains no `devToolsMarker`; with `staging` it does.
- S6 `sinew_devtools_ui` (#45): the overlay and every built-in page, the same as Kotlin's.
  - `SinewDevTools(child:, sections:, ribbon:, launcher:, redaction:, stores:, changelog:, hosts:, showUncaughtErrors:, preferences:)` and `DevToolsMenuItem`. The dashboard is its own `MaterialApp`, so its own theme and navigator. System back on its first screen closes it.
  - `devToolsMarker` (`sinew-devtools-included-7f3a`) is referenced by `SinewDevTools`, for the gating check.
  - `DevToolSection`, `DevToolPage`, `DevToolGroup`, `DevToolToggle`, `DevToolAction`, `BuildRibbon`, `FloatingLauncher`, `MenuLauncher` and `CustomLauncher`.
  - The same pages and rules as Kotlin. `showUncaughtErrors` defaults to on except in debug.
  - `DevTools.open()`, `close()` and `isOpen`. The recorders' `redaction` can be set. `sinew_devtools` re-exports `InspectableStore`, `KeyValueStore` and `SecureStore`, so the UI needs no edge of its own to storage.
  - Tests: widget tests and golden tests, with golden references per OS under `test/goldens/<os>/`. CI uploads the Linux set it records.
- S6 `sinew_network` and `sinew_devtools` (#44, the rest): devtools' way into a client. Closes #44 with the recorders that landed before.
  - `SinewHttpHooks` (`attached`, `hostOverride`, `fault`, `record`; `none` by default). The preset now runs `SinewRecorderInterceptor` **before** the auth interceptor, so it sees a 401 before auth replays it, and `SinewHooksInterceptor` **after** it, so a forced 401 runs the real refresh. `SinewHttp.dio(…, hooks:)` takes them, and so does `mockHttp`.
  - A `FaultDecision` waits, drops the connection (a `connectionError`, so `NoInternetConnectionException`) or answers a status and body without reaching the network.
  - `SinewHttp.debugExpireToken(dio)`: the next request that carries a token sends an invalid one, so the real 401 → refresh runs.
  - Devtools: `FaultRule` and `FaultRules` (in memory only, newest match wins), `HostOverride` (the choice remembered in `sinew.devtools.apiHost`), and `DevTools.httpHooks`, `faults`, `hosts`, `canReplay`, `replay` and `expireAccessToken`.
  - A replay goes through the `Dio` that sent the record, with a fresh token and the client's own headers. A record that lost a secret or was cleared can't be replayed.
  - Fixed while testing: a JSON string response (`"v2"`) is recorded as JSON, not as bare text that redaction then masked whole.
- S6 `sinew_devtools` (#44, the recorders): this part of #44 lands with Kotlin's #43. The HTTP hooks, `FaultRules`, `HostOverride` and replay follow with Kotlin's #44.
  - `NetworkRecorder` (capacity 200, newest first, a `ValueListenable`): `record(NetworkExchange)` redacts before storing, using the client's `defaultHeaders` too. `recordCacheServe` covers responses served from a cache.
  - `NetworkRecord.replayable` is true only when nothing but `Authorization` or the client's own headers lost a value and the body wasn't cut or binary. `asText()` and `asCurl()` give the redacted record.
  - `ExceptionRecorder` (capacity 50): repeats within 2 s of the last are merged into one row with a count, moved to the top. Messages, stack traces and causes go through the new `Redaction.redactText`.
  - `DevToolsCrashReporter(wrapping:)` sends every report to the log, then on to the real reporter unchanged.
  - `DevTools.captureUncaughtErrors()` chains into `FlutterError.onError` and `PlatformDispatcher.instance.onError`. The previous handlers run first, and the platform handler keeps their answer.
  - `DevTools.clearUserData()` empties the network records.
  - `sinew_devtools` now depends on `sinew_exception` and `sinew_models` directly, which are added to the dependency graph.
- S6 `sinew_devtools` (#43): `Redaction`, which masks secrets before anything is stored. Names are normalized (lowercased, without `_`, `-` and `.`) and matched by part (`password`, `token`, `secret`, `otp`, `pin`, `apikey`, …) or whole (`code`), in headers, query parameters, form bodies and JSON bodies at any depth. `Authorization`, `Cookie`, `Set-Cookie`, `Proxy-Authorization` and every `defaultHeaders` name (`withHeaders`) are masked. A JSON body that doesn't parse is masked whole; binary bodies keep only type and size, and a `TextBody` says whether anything in it was hidden (`masked`, so a request that lost a secret is never replayed); fragment parameters (`#access_token=…`) are redacted like the query; text is cut at 64 KB after redaction, keeping its real size. `Redaction.standard.extend(...)` can't remove a default. `Redaction.maskSecret` shows a stored secret as `•••• 9f2c (412 chars)`, or only its length under 16 characters. Replaces the S0 placeholder.
- S5 example (#36): the list screen, through `Pager` → `PagingState` → `toCamoOf` → `CamoPagedList` on the Riverpod mixins, with a mock backend in memory whose second page fails once per list. One full-cycle test (skeleton, items, more items, a failed next page and its retry, a refresh by the pull and by the button, the end of the list) runs as a widget test and in Chrome, and as an integration test on Android, iOS, macOS, Windows and Linux, with a new CI job per platform. `camouflage_core` is overridden to its pinned source for the whole workspace, because Camouflage's packages depend on it by version.
- S5 `sinew_camouflage` (#35): `PagingState.toCamo(localizer)` per the mapping table, and `toCamoOf(context)` with Sinew's localizer for the context's locale; replaces the S0 placeholder. Camouflage isn't published yet, so `camouflage_core` is a git dependency at a pinned commit, with `publish_to: none`. This must become a released version before 1.0.
- S2 `sinew_paging`: `LoadType`, `PagingState` (`canLoadMore`, `retryType`), the strategies behind `Pager.offset`, `offsetByTotal`, `cursor` and `lastItem`, and `Pager.load` (stale responses dropped by request id, `initial` once per query, a `CancelException` leaves the state unchanged, `itemKey` de-duplication) and `cancel()`. `sinew_testing`: `ControlledFetch`, a paging fetch the test answers call by call. `sinew_models`: `ViewState` and `Result` equality ignores type arguments, so a `const` default (`Loading<Never>`) equals an explicit state both ways round.
- S1 `sinew_l10n`: `SinewLocalizer` (and `SinewLocalizer.of(context, appStrings:)`): the app's strings first, then Sinew's English and Indonesian for the page's locale, mapping each `sinew.error.*` key to its generated getter; replaces the S0 placeholder. Tests check every built-in key in both languages, English equal to each exception's fallback, the ARB placeholders, and a locale switch re-rendering an error on screen.
- S1 `sinew_exception`: the 20 built-in types (including `CancelException`), `ExceptionHandler`, `envelopeDataMissing`, `processCall` (pass-through, first-match handlers, Dart `Error`s caught, unexpected and parse failures reported with their stack trace), `processUseCase`, `CrashReporter` (`none`, `install`, `current`), `Localizer` and `displayMessage`.
- S1 `sinew_models`: `Domain` (value equality from `props`), `Remote`, `Entity`; the error base contract (`SinewException`, `ExceptionLayer`, `ErrorMessage` with `ServerMessage` and `LocalMessage`, `EnvelopeDataMissing`); `Envelope` with the optional `failure()` and `message()` hooks, `EnvelopeFailure`, the four envelope bases, `PagingMetaEnvelope` and `unreachableDomainFromJson`; `PagingDomain`, `PagingMetaDomain`, `PagingEntity`, `ViewState` and `Result` (`Success(data, message)` / `Failure(error, stackTrace)`).
- S0: workspace skeleton. One package per Sinew package in a pub workspace managed by Melos, the dependency-graph check (`tool/check_graph.dart`), `sinew_l10n`'s generated and committed localizations (English, Indonesian), and the example app for all six platforms.
